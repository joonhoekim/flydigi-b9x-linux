표기: 바이트는 16진수, `[n]` 은 프레임의 n번째 바이트(0부터).
**확정** 은 조작과 패킷이 1:1 로 맞은 것, **추정** 은 값의 변화만 보고 해석한 것.

## GATT

| handle | UUID | 용도 |
|---|---|---|
| 0x0038 | `ffe1` | 명령 write (write without response) |
| 0x003b | `ffe4` | notify. CCCD 0x003c 에 `01 00` |
| 0x0034 | `fee1` | 앱이 쓰지 않음 |
| 0x0023–0x0030 | `2a4a`·`2a4b`·`2a4d`… | HID 서비스. 앱이 쓰지 않음 |

서비스·특성 UUID 는 B8X·B6 와 같다(`ffe0` / `ffe1` / `ffe4`).
notify 는 항상 20바이트로 오고, 유효 길이 뒤는 이전 버퍼 찌꺼기다.

## 연결 직후 앱의 순서

```
-> CCCD 01 00
<- 30 2e 33 2e 30 00                펌웨어 버전 ASCII "0.3.0" (요청 없이 옴)
-> a5 a0 00 00                      핸드셰이크
<- a5 a0 19 30 f0 f1 f2 f3 f4 | 83 f4 c5 64 7f 9c | 00 00 00 00 03
                                    뒤쪽 6바이트는 MAC 역순
-> 51 00                            현재 LED 설정 조회
-> 22 04  <- 22 04 05 05 05 06 07 08 08 08 08     Custom 커브 조회
-> 24 00  <- 24 83 f4 c5 64 7f 9c                  MAC 조회 (역순). B6 와 같음
-> 61     <- 61 00 00 00 00 …                      예약 종료 조회. 이후 화면 전환마다 24 00 과 함께 반복
-> 52 00                            응답 없음 (B6 에선 실험 설정 조회)
```

BS3 Pro 펌웨어의 `0x0B` 응답도 `19 31 f0 f1 f2 f3 f4` + MAC 이다 (ElXreno/flydigictl).
`19 3x` 는 제품군 식별자로 보인다 (B9X `30`, BS3 Pro `31`).

앱이 서버로 보내는 `uuid=2548240241242243244131244197` 은
`a5 a0` 응답 앞부분(`19 30 f0 f1 f2 f3 f4 83 f4 c5`)을 10진수로 이어 붙인 값이다.

`13` 을 보내지 않아도 상태 프레임이 약 1초마다 push 된다.

## 상태 프레임 `13` (20바이트, 1 Hz)

예: `13 00 02 91 28 00 06 08 04 2a 2d c9 25 32 ff 0c 01 03 00 00`

| 위치 | 예 | 해석 | 근거 |
|---|---|---|---|
| [0] | `13` | 프레임 종류 | 확정 |
| [2] | `02` | 상위 니블 = 모드 (0 Smart, 1 Fixed, 4 Custom). 하위 니블은 늘 2 | 확정 |
| [3] | `91` (145) | 냉각 설정값 | 확정 (프리셋 전환과 일치) |
| [4][5] | `28 00` | 팬 설정값 = `[4]*100+[5]` = 4000 | 확정 (프리셋 전환과 일치) |
| [6] | `06` | Smart 의 세부 프리셋: 06 Silent, 00 Max. 다른 모드에선 00 | 확정 (`20` 의 [5] 와 같은 값) |
| [7][8] | `08 04` | 냉면 온도. 정수부 `signed([7])`, 소수부 `[8]/10`, 부호는 전체에 붙는다 (아래) | 확정 (앱 화면과 대조) |
| [9] | `2a` | 열면 온도 °C (42). 앱은 숫자 대신 "Normal" 로만 표시 | 추정 (OC 중 34→45 로 상승) |
| [10] | | 실제 냉각 출력. 설정값 근처에서 변동, OC 중 `b8`(184) 고정. 앱의 "Cooling Strength"(Weak 등)는 이 값으로 보임 | 추정 |
| [11] | | 미확인. OC 를 켜면 `7f`→`dc` 로 올라가 유지, 끄면 서서히 내려감. 전류·전력 계열일 수 있음 | 추정 |
| [12][13] | `25 32` | 실측 팬 RPM = `[12]*100+[13]` = 3750 | 확정 (앱 Fan speed 3930 = `27 1e`) |
| [14] | `ff`/`00` | 조명 켜짐/꺼짐 | 확정 |
| [15] | `0c` | 현재 LED 효과 번호. 모드마다 따로 저장된다 (Smart 0c, Custom 03, Fixed 04) | 확정 |
| [16] | `01` | 롱프레스 모드 (`21` 로 설정) | 확정 |
| [17] | `03`/`83` | bit7 = OC Experience 켜짐 | 확정 |

### 냉면 온도 계산

```
t = |signed([7])| + [8]/10
temp = -t if [7] >= 0x80 else t
```

OC 로 냉면을 영하로 내리고 앱 화면과 대조해 확정했다.

| 앱 화면 | [7] [8] | B8X 식 `signed([7]) + [8]/10` |
|---|---|---|
| -5.1 °C | `fb 01` | -4.9 (틀림) |
| -8.4 °C | `f8 04` | -7.6 (틀림) |
| -9.1 °C | `f7 01` | -8.9 (틀림) |
| 6.1 °C | `06 01` | 6.1 |

B8X 의 `parse_status()` 는 바이트 위치는 맞지만 음수 온도를 틀리게 계산한다.
또 B8X 코덱의 설정 범위(팬 4000–4500, 냉각 92–175)는 B9X 프리셋(팬 5500·5700)과 맞지 않는다.

## 모드

### 설정 `20` — Smart / Fixed

```
20 <mode> <cold> <wQ> <wR> <x> <cold> <wQ> <wR>
```

`wQ = 팬/100`, `wR = 팬%100`. 같은 3바이트를 두 번 보낸다. B8X 와 같은 틀이다.
`x` 는 Smart 의 세부 프리셋(06 Silent, 00 Max)이고 상태 프레임 [6] 에 그대로 나온다.

| 앱 표시 | 명령 | 냉각 | 팬 |
|---|---|---|---|
| Smart · Max | `20 00 af 37 00 00 af 37 00` | 175 | 5500 |
| Smart · Silent | `20 00 91 28 00 06 91 28 00` | 145 | 4000 |
| Fixed · Energy saving | `20 01 91 28 00 00 91 28 00` | 145 | 4000 |
| Fixed · Strong | `20 01 9b 2d 00 00 9b 2d 00` | 155 | 4500 |
| Fixed · Max | `20 01 af 39 00 00 af 39 00` | 175 | 5700 |

모드 탭만 바꿀 때 앱은 값을 0 으로 채워 보낸다 (`20 01 00…`).
Smart 로 돌아갈 때는 `x` 만 채운다 (`20 00 00 00 00 06 00 00 00` → Silent).
기기는 그 모드에 저장된 프리셋을 적용하고 상태 프레임으로 알려준다.

### 설정 `20 04` — Custom (냉각 계획 커브)

```
20 04 <L1> <L2> … <L9>        각 Ln = 1–8 (앱의 level 1–8)
```

- knob 를 움직일 때마다 9개 값 전체를 바로 보낸다. 별도의 저장 명령은 없다.
- 앱의 "저장" 은 `22 04` 로 다시 읽어오는 동작이다.
- 탭 전환 시에는 `20 04 00 × 9` 를 보낸다 (저장된 커브 유지).
- Custom 모드의 상태 프레임 [3]–[5] 는 `a0 2d 00` (160 / 4500) 으로 고정되어 보인다.
- 9개 knob 의 x축은 냉면 온도 -12, -9, -6, -3, 0, 3, 6, 9, 12 °C (앱 "Curve Settings" 그래프). 각 온도에서의 냉각 강도 레벨이다.

### 조회 `22 04` → `22 04 <L1> … <L9>`

캡처 1 의 응답 `05 05 05 06 07 08 08 08 08` 도 커브였다.

### Quick switch (롱프레스 모드) `21 <mode>`

앱의 "Quick switch". 기기 전원 버튼을 길게 누르면 현재 모드와 이 모드 사이를 오간다.
값은 `20` 의 mode 와 같다 (00 Smart, 01 Fixed, 04 Custom). 상태 프레임 [16] 에 반영된다.

- 기본 모드를 바꾸면 앱이 Quick switch 를 **직전 모드**로 함께 바꾼다.
  예: Smart→Custom 이면 `21 00`, Custom→Smart 면 `21 04`, Fixed→Smart 면 `21 01`.
- 현재 모드와 같은 값은 앱에서 고를 수 없다 (회색 처리).

## OC Experience `26 <on> 00 00`

| 명령 | 의미 |
|---|---|
| `26 01 00 00` | 켜기 — 앱 경고: 최고 출력 고정, 과냉각 보호 해제 |
| `26 00 00 00` | 끄기 |

켜는 동안 상태 프레임 [17] bit7, [10] = `b8`(184). 약 3분 만에 냉면이 -9 °C 까지 내려갔다.
앱 표시 이름은 "OC Experience", 경고 창 제목은 "You are experiencing freezing mode".

## 예약 종료 (Scheduled Shutdown)

### 설정 `60 <repeat> <enable> <min_hi> <min_lo>`

| 앱 조작 | 명령 |
|---|---|
| One Time Only, 1시간 2분 | `60 00 01 00 3e` |
| Repeat, 1시간 2분 | `60 01 01 00 3e` |
| 끄기 | `60 01 00 00 3e` (마지막 설정의 나머지 값을 그대로 둠) |

분 단위 총합(62 = `0x003e`)을 2바이트로 보낸다. 바이트 순서는 255분이 넘는 값으로 확인하지 않았다 (빅엔디언 추정).
앱 안내: 예약 종료를 켜면 조명이 "예약 조명 효과"로 바뀐다.

### 조회 `61` → `61 <repeat> <enable> <min_hi> <min_lo> …`

뒤 15바이트는 버퍼 찌꺼기. 끄면 `<repeat>` 도 00 으로 읽힌다.

## LED 효과

LED 효과는 냉각 모드(Smart / Custom / Fixed)마다 따로 저장된다. Light 화면에서 바꾸면 현재 모드의 효과가 바뀐다.
기기 전원 버튼을 빠르게 두 번 누르면 효과가 순서대로 바뀐다 (앱 안내).

### 쓰기 `50` (20바이트)

```
[0]  50
[1]  effect
[2]  speed            효과별 값 (아래 표). 속도 없는 효과는 00
[3]  ncolors          1–8
[4]  pkt              01, 02 (색이 5개 이상이면 두 프레임)
[5..16]  RRGGBB × 4   이 프레임에 담긴 색. 남는 칸은 00
[17] brightness       20–100 (0x14–0x64). 앱 슬라이더 최소가 20
[18] color mode       앱이 쓸 때 보통 00. Rhythm 만 01 Single color / 02 Colorful
[19] sum              [0..18] 합의 하위 8비트
```

- 색은 앱 색상 휠에서 고른 RGB 가 그대로 들어간다 (밝기로 스케일하지 않음).
- 8색이면 `pkt` 01 에 1–4번째, 02 에 5–8번째 색. 두 프레임 모두 [2][3][17] 을 같은 값으로 채운다.
- 효과만 바꿀 때는 `50 <effect> 00 … 00 <sum>` 을 보내고, 바로 `51 <effect>` 로 저장된 설정을 읽는다.
- 앱에서 색 삭제·추가·속도·밝기를 바꿀 때마다 전체 설정을 다시 보낸다.

### 조회 `51 <effect>` → 응답

```
51 <effect> <speed> <ncolors> <pkt> <RRGGBB × 4> <brightness> <color mode> 00
```

쓰기와 같은 배치에서 [19] 체크섬 자리가 00, [18] 이 01(일반)/02(Colorful) 로 온다.
`51 00` 은 현재 효과를 조회한다.

### 효과 목록

앱 드롭다운 순서. 번호는 `50`/`51` 의 effect, 앱 로그 `ledType` 은 이 번호의 10진수.

| 번호 | 앱 표시 | 앱 내부 이름 | 색 | 속도 (저/중/고) | 비고 |
|---|---|---|---|---|---|
| 0c | Smart Control | rainbowSmart | 변경 불가 | 없음 | 냉각 출력에 따라 자동 (고출력=따뜻한 색·빠름) |
| 03 | Flow | rainbow | 변경 불가 | 6 / 4 / 2 | |
| 06 | Gradient | gradual | 최대 8 | 10 / 8 / 6 | |
| 05 | Breathing | breath | 2–8 | 8 / 5 / 3 | |
| 04 | Cutover | — | 2–8 | 8 / 5 / 3 | |
| 0b | Always on | long | 1 | 없음 (00) | |
| 10 | Multi-color Rotation | rotationMultipleColor | 2–8 | 8 / 5 / 3 | |
| 11 | Pulsating | throb | 2 (고정) | 없음 | |
| 13 | Rhythm | rhythm | 1 | 없음 | Single color / Colorful ([18]) |
| 14 | Cyberpunk | cyberpunk | 변경 불가 | 없음 | |
| 15 | Collision | collision | 2–8 | **3 / 5 / 8** | 다른 효과와 방향이 반대 |

- 속도 값은 대부분 작을수록 빠르다. Collision 만 클수록 빠르다.
- 색 최소 개수는 앱이 강제한다 ("… requires at least 2 color(s)"). Gradient 의 최소는 확인하지 않았다.
- 앱의 Reset 은 효과별 기본 색으로 되돌린다 (Always on 은 흰색 `ff ff ff`, 8색 효과는 빨강→주황→노랑→초록→청록→파랑→보라→분홍).
